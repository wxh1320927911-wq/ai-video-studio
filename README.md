## 一、必须先纠正的三个前提

最初的设计假设「在 AutoDL 租一台普通 GPU 容器实例就能跑 H3-Base」。实际核对后发现：

| 最初设想 | 实际情况 |
| --- | --- |
| 租一台普通 GPU 实例 | H3-Base 官方推理路线（SGLang / vLLM）**需要 4 张 80GB 卡**；单卡必须走 ComfyUI 量化路线 |
| 本地能出高分辨率 | **本地任何显卡都只能出 768p（短边 768px）**。2K 依赖未开源的 H3-Regenerate-2K，只能走官方托管 API |
| H3 是一个模型 | 开源的是 **H3-Base** 一个模块；H3-Context-IR（指令理解编排）和 H3-Regenerate-2K（2K 再生成）**没有开源**，只有 API |

**结论：第一阶段走单卡量化 ComfyUI 路线**（已确认选择）。官方路线留作以后批量生成时再评估。

## 二、H3-Base 已核实的事实

来源：[MiniMax-AI/MiniMax-H3](https://github.com/MiniMax-AI/MiniMax-H3)、[Comfy-Org/MiniMax-H3](https://huggingface.co/Comfy-Org/MiniMax-H3)、[ComfyUI 官方教程](https://docs.comfy.org/tutorials/video/minimax/minimax-h3)

| 项目 | 事实 |
| --- | --- |
| 架构 | 33B 稠密单流 Omni Transformer（其中约 13B 在 AdaLN 分支，剪枝版可去掉）+ Qwen3-VL-32B 作编码器 |
| 开源范围 | 仅 H3-Base（768p 生成）；Context-IR、Regenerate-2K 未开源 |
| 开源的两个 checkpoint | **FL2VA**（文生 / 首帧 / 尾帧 / 首尾帧）和 **Ref2VA**（图像·视频·音频参考）。**两套权重不通用** |
| **稀疏注意力未开源** | H3 原生支持稀疏注意力训练与推理，但官方 README 原文：*"The initial open-source release provides inference with **full attention only**. Our sparse-attention implementation will be released in a future update."* —— **首次开源版只有全注意力**，这是本地推理慢的一个结构性原因，也意味着将来官方放出来会有一次免费提速 |
| 官方推荐的服务框架 | SGLang、vLLM、diffusers、**ComfyUI** —— ComfyUI 是官方认可的路线之一，不是社区野路子 |
| 输出分辨率 | 短边 768px；16:9 即 1344×768。分辨率取整到 32 的倍数 |
| 输出时长 | 4–15 秒，帧数对齐 17k+5 网格（24fps 下即 5、22、39、56… 帧） |
| 音频 | 每次生成自带 32kHz 立体声，与画面同一次前向产出，不需要后期配音 |
| 对白语言 | 稳定支持 11 种，含中文、英语、日语、韩语 |
| 提示词上限 | 7000 字符；请求体 ≤ 64MB |
| 许可 | MiniMax H3 Community License。**本地生成结果商用需通过 Comfy 购买商用许可** |

> **一句话：本地能跑的，全都是 H3-Base。** 这不是巧合，是逻辑必然——H3 系统三个模块里只有 H3-Base 开源了权重。
> 所以任何 ComfyUI 应用、任何社区镜像、任何本地部署，跑的都是 H3-Base 的 FL2VA 或 Ref2VA，**上限就是 768p**。
> 但要区分「同一份权重的不同包装」和「换了一份权重」：剪枝量化版（Comfy-Org 打包的 21GB）是前者；蒸馏版（如 FastVideo 的 FastH3 8 步检查点）是后者，严格说已经不是原版 H3-Base 了；turbo LoRA 则只是挂在基座上的小补丁，基座没变。

## 三、路线决策

| 路线 | 硬件 | AutoDL 时价 | 适用 |
| --- | --- | --- | --- |
| **单卡量化 ComfyUI（当前选择）** | 1×24–32GB 显存 + ≥32GB 内存 | ¥1.32–2.78/时 | 第一到第二阶段：跑通、测成本、写提示词、做短片 |
| 4 卡官方 SGLang | 4×80GB | ¥22.36–39.92/时 | 以后确定要批量生成时再评估 |
| 云 API 对照 | 无 | 2K 约 ¥0.8/秒 | 只用来对照效果，不作为主路线 |

AutoDL 各卡单价（2026-09 官网现价，以网站为准）：

| 卡型 | 显存 | 单价 |
| --- | --- | --- |
| RTX 3090 | 24GB | ¥1.32/时 |
| RTX 4090 | 24GB | ¥1.88/时 |
| RTX 5090 | 32GB | ¥2.78/时 |
| A800-80GB | 80GB | ¥5.59/时 |
| PRO 6000 | 96GB | ¥6.98/时 |
| H800 | 80GB | ¥9.98/时 |

**第一阶段选 4090（¥1.88/时）**：显存够 pruned int8 驻留，速度比 3090 快一倍以上，价格只有 5090 的 68%。5090 的原生 NVFP4 优势要等第二阶段提速时再考虑。

### 规划机（跑本地文字模型）

家里的 12GB 显卡暂时不在手上，过渡期单独租一台跑提示词模型。**选 RTX 3090 / 24GB**，理由和模型选择见 `docs/04-规划机选型.md`，后续调整见 `docs/05-解禁模型与主机调整.md`。

> **2026-09-20 更新**（以 `docs/05-解禁模型与主机调整.md` 为准）：
> ① 官方 `qwen3.6:27b` 带安全对齐，写黑暗向内容会拒答，换解禁模型。全站筛选后**主选 `JonathanColetti/Qwen3.8-27B-Uncensored`（Q4_K_M，实测 15.66GB）**——它是唯一零微调的候选，格式能力与基座等价；DavidAU 那版降为 A/B 对照组，0bserverx 版作第二替补。
> ② 3090 全平台有 612 张空闲卡，但**只在 北京A区（¥1.32）/ 内蒙B区（¥1.48）/ 西北企业区（¥1.58）**有货，西北B区、重庆A区是 0。建议选内蒙B区求库存稳定。
> ③ **已实测通过**：10 条验证创意（含 5 条暴力/死亡/持械/伤情/威胁题材）**拒答 0 条、一次通过 10 条**，整批 112 秒。官方基线组取消（决定不下官方版）。结果在 `records/abtest/`。
> ④ 关键配置一：**思维链默认关闭**（两个跑批脚本都是默认关，要开加 `--think`）。实测开着 xhigh 思维链慢 17 倍、正文反而更短，还会挤爆 `max_tokens` 预算。细节见 05 文档 9.2。
> ⑤ 关键配置二：**MTP 投机解码默认开启**（`start-planner.sh` 里 `MTP=1`，启动失败会自动去掉该参数重试）。实测提速 **1.44 倍**（39.6 → 59.4 tok/s；整批 100.3 → 69.7 秒），投机解码按构造无损，质量判据逐条一致。细节见 05 文档 9.9。
> ⑥ 注意：中途一度测出"100% 通过"，实为检查器盲区——补上对白标记、画外音成对两条判据后真实水平只有 40%，加固提示词后才真正到 100%。**看通过率先怀疑检查器**。详见 05 文档 9.3。
> ⑦ **网页入口**：`llama-server` 自带聊天界面，但原脚本绑在 `127.0.0.1:11434`——而 AutoDL 只映射 6006/6008，所以从外面根本打不开。已改为 `0.0.0.0:6006`，起服务后回 AutoDL 控制台点「自定义服务」即可用浏览器对话。**公网可达，建议设 `API_KEY=`**。详见 05 文档 9.11。
> ⑧ **换台电脑怎么访问**：两条路——①「自定义服务」复制出的公网地址，任何电脑浏览器直接开，零配置但要配 `API_KEY`；②SSH 隧道 `ssh -CNg -L 6006:127.0.0.1:6006 -p 33780 root@connect.nmb2.seetacloud.com`，不暴露公网但要保持终端开着。**前提都是实例得先开机。** 详见 05 文档 9.12。
> ⑨ **视觉可用**：`mmproj` 不只加载成功，已实测能正确读图（识别出图上的文字与颜色）。详见 05 文档 9.10。

一句话概括：决定性变量是显存容量而不是算力。24GB 才能跑 Qwen3.6-27B 这个档位，而写 H3 提示词要求严格的结构化输出，14B 级别会丢字段、乱标签。3080Ti（12GB）被排除是因为家里已经有 12GB 卡，租它等于复刻已有能力。

## 四、本地 / 云端分别保存什么

| 本地电脑 | AutoDL 实例 |
| --- | --- |
| 剧本、人物与场景设定 | ComfyUI 与推理环境 |
| 完整分镜、总时间线、H3 提示词 | H3 模型权重（数据盘，约 42GB） |
| 生成记录、已下载片段、最终成片 | 生成中的中间结果与日志 |
| 任务清单与费用记录 | 系统盘里的 ComfyUI 代码与依赖 |

传输的只有**提示词、参考素材和生成结果**，模型权重只在实例上放一份，不需要来回搬。

## 六、费用要点（最容易踩的坑）

1. **按量计费从开机算起，关机才停。** 关浏览器、断 SSH 都不算关机。改提示词时开着卡就是在烧钱。
2. **先在本地把提示词写完，再开云端。**
3. **付费扩容的数据盘无论是否开机都每天计费。** 用完及时缩容或释放实例。
4. **保存镜像不等于备份数据盘。** 数据盘内容不会进镜像，模型只能留在数据盘上。
5. **关机就停计费，且数据全保留**（系统盘+数据盘都在），所以「暂时不用」应该关机而不是硬开着。但**连续关机 15 天实例会被自动释放**，这是硬期限——本轮关机后对应 **2026-10-05**。详见 `docs/05` 第 9.8 节。
6. **实验做完立刻关机，别让实例空转着等决策。** 本轮就是因为"等停放方案决定"多烧了约 20 分钟（≈¥0.5）。决策可以在关机的状态下慢慢做。
7. 首次部署大头是「下载 42GB 模型」和「装环境」，这两步合计约 1–2 小时。可以用无卡模式（¥0.1/时）先做，但要接受之后可能抢不到卡的代价。
8. 规划机这一轮的账：**1 小时 34 分 / 约 ¥2.3**，其中编译+下载占了近一半时间——那部分是可复用的，下次开机 10 秒加载完权重就能用。

费用记录写在 `records/` 下，每次租卡都记一行，用来判断这条路值不值。
