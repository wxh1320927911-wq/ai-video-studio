# 02 · 以后每次创作的固定流程

> 首次部署做完一次就不用再做了。这份是每次真正做作品时走的流程。
> 核心纪律只有一条：**在本地把方案和提示词全部定稿，再开云端。**

---

## 全流程

```
① 本地：写方案和提示词（不花钱）
   创意 → 场景/人物设定 → 分镜与总时间线 → 每段的 H3 提示词
   ↓ 你检查、修改、定稿
② 云端：开机生成
   控制台开机 → 启动 ComfyUI → 浏览器打开
   ↓ 逐段提交
③ 云端：逐段生成 → 逐段检查
   不合格 → 改提示词 → 重生成
   ↓ 本批全部通过
④ 云端：下载结果 → 关机（立刻）
⑤ 本地：拼接、字幕、声音处理、导出成片
```

---

## ① 本地：写方案和提示词

这一阶段完全不碰云端。产出物是**一个批次的提示词清单**，每一条都对应一个片段。

一个片段的规划要写清楚：

| 字段 | 说明 |
| --- | --- |
| 片段编号 | 如 `S03` |
| 时长 | 4–15 秒，且会对齐到 17k+5 帧网格 |
| 画幅 | 16:9 / 9:16 / 1:1 … |
| 任务类型 | T2VA（纯文）/ I2VA（首帧）/ FL2VA（首尾帧）/ R2VA（参考） |
| 提示词 | 按 `03-H3提示词写法.md` 的三字段结构写 |
| 参考素材 | 该片段需要的图片/视频/音频文件路径 |
| 与前后片段的衔接 | 上一段的结尾状态、下一段的起始状态 |

**一致性靠素材，不靠文字。** 模型不会记住你的故事，角色长相和场景风格必须靠共享的参考图/参考视频来锁定（走 Ref2VA 或首尾帧）。文字只负责描述这一段里发生了什么。

草稿放 `prompts/`，文件名建议 `S01-描述.md` 这样，方便和生成结果对照。

### 文件放哪

**本地这份是唯一真源，实例只是临时工作区。**

| 内容 | 位置 |
| --- | --- |
| 系统指令 | `prompts/system-prompt.txt` |
| 提示词模板 | `prompts/templates/`（T2VA / I2VA / FL2VA 三份） |
| 创意输入 | `prompts/briefs/`，每条一个 txt，文件名 = 片段编号 |
| 提示词产出 | `prompts/output/`，与 brief 同名 |
| 参考素材原件 | `assets/` |
| 写法规范 | `docs/03-H3提示词写法.md` |

上传下载都走 JupyterLab 左侧文件树。跑完把 `output/` 整个下载回来，立刻关机。

> ⚠️ **Open WebUI 里存的助手不算存储。** 它的数据默认存在实例本地的 SQLite 里，实例一释放就全没了。真源永远是本地那份 `system-prompt.txt`。

细节见 `prompts/README.md` 和 `assets/README.md`。

---

## ② 云端：开机

1. AutoDL 控制台 → 实例 → 开机。
2. 等实例状态变成「运行中」。
3. 开 JupyterLab 终端，启动 ComfyUI：

```bash
cd /root/autodl-tmp/ComfyUI
nohup python main.py --listen 0.0.0.0 --port 6006 > /root/autodl-tmp/comfyui.log 2>&1 &
```

4. 控制台点「自定义服务」，复制地址，本地浏览器打开。

**从这一刻起开始计费。** 别开着卡去写提示词。

---

## ③ 云端：逐段生成与检查

- 一次只提交一个片段，生成完立刻看。**不要一次性把十条都排队**——前一条的毛病往往后一条也有，批量跑等于批量浪费。
- 检查四件事：动作是否合理、角色是否和上一段一致、画面里有没有乱码文字、音频（对白/音效）对不对。
- 不通过就改提示词重跑。改的时候参考 `03-H3提示词写法.md` 里的「常见问题对应改法」。
- 生成记录（用了哪条提示词、多少步、耗时）记在 `records/` 里。

**批量技巧**：本批如果超过 5 条，可以先把每条都用 `Megapixels 0.4` + turbo 8 步跑一版「草稿」，全部确认动作和构图没问题，再把通过的片段用满画布（`0.98`）+ 20 步重跑一遍正式版。这样废掉的都是便宜的草稿。

---

## ④ 云端：下载与关机

1. 到 ComfyUI 的 `output/` 目录，用 JupyterLab 右键下载，或走 AutoPanel 公网网盘。
2. **确认文件已经完整下载到本地**（打开看一眼，能正常播放）。
3. 立刻关机。控制台点关机，计费才停。
4. 记账：日期、卡型、开机时长、生成条数、花费。

> 顺序很重要：**先确认下载成功，再关机**。关机后虽然数据不会丢，但万一要重新开机下载，就又要等一次 GPU。

---

## ⑤ 本地：合成

H3 每次生成都自带 32kHz 立体声，所以本地这一阶段主要做的是：

- 按总时间线把片段依次拼接
- 处理片段之间的转场和节奏
- 需要的话加字幕
- 统一音量、必要时替换或叠加音乐
- 导出成片并归档

推荐工具：**DaVinci Resolve**（免费版够用，剪辑 + 音频 + 字幕一体）。片段是 24fps，工程帧率设成 24fps，避免二次插帧。

---

## 时间线怎么管

分两层，别混在一起：

| 层级 | 内容 | 谁负责 |
| --- | --- | --- |
| **总时间线** | 整部作品的片段顺序、每段时长、累计时间点 | 本地，你维护 |
| **片段内时间线** | 这一段里的镜头切换、动作、对白时点 | H3 提示词里描述 |

H3 每次只认自己这一段里的时间（首镜无时间戳，后续镜头用 `At 00:03.500,` 这种递增写法）。它不知道也不关心整部片子有多长。

**需要注意**：模型对片段内部时间的遵循是近似的，提示词里写「第 3 秒切换」不代表一定精确在第 3 秒切。所以：
- 需要精确卡点的镜头，**拆成独立片段**分别生成，靠剪辑对齐，不要指望一次生成里精确控制。
- 片段之间如果需要严格衔接，用上一段的**末帧作为下一段的首帧**（FL2VA），比用文字描述衔接可靠得多。

---

## 每批做完要记的四件事

写进 `records/`，累计起来才有判断依据：

1. 本批生成条数、废掉几条
2. 开机总时长、花费
3. 单条平均成本（元/条、元/秒成片）
4. 遇到的新问题（提示词坑、参数坑）

跑过 3–4 批之后，用这张表对比一下官方 API 的价格（2K 约 ¥0.8/秒），就能算出「自建」和「调 API」哪个更划算，再决定要不要上 4 卡官方路线做批量。
