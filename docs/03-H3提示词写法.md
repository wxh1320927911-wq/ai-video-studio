# 03 · H3 提示词写法

> 来源：MiniMax 官方 [Base 模式提示词指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)、[Full-reference 指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)、官方 [h3-prompt-writing 技能](https://github.com/MiniMax-AI/MiniMax-H3/tree/main/skills/h3-prompt-writing)，以及 [ComfyUI 提示词指南](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide)。
> H3 和别的视频模型最大的不同：**画面、镜头、对白、音效、配乐全部写在同一个提示词里**，因为它是音视频同一次前向生成的。
>
> **与官方的对照结论（2026-09-20 逐条核对）**：第一~六节的字段名、字段顺序、对齐指令、标签语法都是官方原文的逐字口径，可以直接用。但初版漏了 **L2VA** 和整个 **Ref2VA**（见第七、八节），已补齐；FL2VA 模板里 `Picture 2 (from Shot 1)` 的写死也有误，已改为 `(from [Shot N])`。
>
> ⚠ **一处未证实的数字**：本文第十节的「提示词 ≤7000 字符」来自平台 API 文档，**在两份官方提示词指南里都没有重申**。`ab-test.py` 把它当硬判据用，如果以后遇到长度被卡，先怀疑这个数。

## 一、提示词的整体结构

```
[第一行：对齐指令（只有图生视频需要，T2VA 不要这行）]

integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

对齐指令后面**必须跟一个空行**。三个字段的顺序不能换。

### 三个字段各写什么

| 字段 | 写什么 | 长度 |
| --- | --- | --- |
| `integrated_multimodal_description` | 沿时间线写：风格、构图、主体外观与位置、场景道具、动作、镜头切换、说话人、对白、歌唱、画内音 | 主体，可以很长 |
| `overall_soundscape` | 环境声、物理动作声、非语言人声（风、雨、脚步、布料摩擦、呼吸、笑声） | 1–4 句，一段 |
| `non_diegetic_music` | 只有观众能听到的配乐。写乐器、速度、节奏、音量变化 | 1–3 句 |

**不要重复**：对白、歌唱、角色能听见的音乐（收音机、电视）属于画内事件，写在第一段，不要在 `overall_soundscape` 里再写一遍。全片静默才写 `N/A`。

`non_diegetic_music` **不要写抽象情绪词**（"悲伤的""宏大的"），写具体的：`Sparse piano notes at a slow tempo, joined by sustained low strings`。

## 二、镜头与时间

- **第一个镜头不加时间戳**，直接从风格和构图开始：
  ```
  [Shot 1] Live-action, cinematic, a medium-wide shot frames a baker opening the shutters...
  ```
- **后续镜头**用递增序号，以严格递增的剪切时间开头，格式 `MM:SS.mmm`：
  ```
  [Shot 2] At 00:03.500, the camera cuts to a close-up of steam rising from the sliced bread...
  ```
- 常用切换词：`the camera cuts to` / `the shot cuts to` / `the shot transitions to`。需要交叉溶解、淡入淡出、划像时可以明确写出来。
- **剪切要带来新信息**（主体、空间、状态、视点、时间变了）。如果只是想靠近一点、转个角度，用镜头运动，不要切。

**风格词**（写在 `[Shot 1]` 开头）：`Live-action`、`Cinematic`、`2D-animated`、`3D CG`、`claymation`、`watercolor`、`vintage film`。

## 三、镜头运动：类型 + 幅度 + 速度

写成镜头内的自然英文句，不要堆标签。

```
The camera pushes in with small amplitude at slow speed toward the folded letter in her hands.
The camera pans right with large amplitude at fast speed, revealing the open doorway.
The camera holds a static shot as the runner exits the frame.
```

| 运动类型 | 含义 |
| --- | --- |
| `Zoom In / Zoom Out` | 变焦，机身不动 |
| `Push In / Pull Out` | 机身前后移动 |
| `Pan Left / Pan Right` | 原位水平转镜 |
| `Truck Left / Truck Right` | 水平平移 |
| `Tilt Up / Tilt Down` | 原位垂直转镜 |
| `Pedestal Up / Pedestal Down` | 机身整体升降 |
| `Arc Shot` | 环绕主体 |
| `Tracking Shot` | 跟随移动主体 |
| `Static Shot` | 完全静止 |
| `Shake Slightly / Shake Strongly` | 抖动 |
| `POV` | 主体视角 |
| `Roll Clockwise / Roll Counterclockwise` | 绕镜头轴滚转 |

幅度：`with small amplitude` / `with large amplitude`。速度：`at slow speed` / `at fast speed`。中等幅度和正常速度可以省略不写。

## 四、对白与说话人

- 会说话、唱歌或发出画外人声的主体给稳定 ID：`(S1)`、`(S2)`。多人同时发声用 `(S1,S2)`。**同一个角色跨镜头保持同一个 ID**；从不发声的角色不给 ID。
- 说话人第一次出现时，要从视听角度交代身份：角色类型、年龄、性别、是否出镜、音高、音色、语速、口音。
- **`<d>` 标签里只放语言标签 + 原始口播内容，逐字逐标点保留，不翻译不改写。** 识别短语、ID、动作、语气都写在 `<d>` 外面。

```
The young woman with a quiet, breathy voice (S1) says: <d>[English] I get off at the next station.</d>
The two children (S1,S2) shout together, <d>[English] Wait for us!</d>
```

- **画外音**用固定短语 `says in an off-screen voiceover`，并且每个画外音 `<d>` 块后面**立刻声明该角色嘴唇紧闭**，否则会出现假口型：
  ```
  The man (S1) says in an off-screen voiceover: <d>[English] I still remember that road.</d> while his lips remain completely closed.
  ```
- 一句台词跨剪切时，在连接处加 `<scenetrans>`，并说明音频跨剪切延续。语音被结尾截断用 `<cutoff>`。

## 五、屏幕上的文字

画面里出现的招牌、横幅、字幕、霓虹字，**用英文双引号包起来，保留原文和标点，不翻译**：

```
A red neon sign reading "营业中" glows above the doorway.
```

要逐条列举每一处文字。不定义的文字容易糊成乱码符号。

> 注意区分：**引号给印在画面上的字**，`<d>` 给角色嘴里说的话。

## 六、标签速查

| 标签 / 写法 | 用途 | 适用模式 |
| --- | --- | --- |
| `[Shot N]` | 镜头序号，首镜无时间戳 | 全部 |
| `At 00:03.500,` | 剪切时间，严格递增 | 全部 |
| `<d>[语言] 原文</d>` | 对白 / 歌词，逐字保留 | 全部 |
| `(S1)` `(S1,S2)` | 说话人 ID | 全部 |
| `<scenetrans>` | 同一句台词跨剪切 | 全部 |
| `<cutoff>` | 语音被结尾截断 | 全部 |
| `"..."` | 画面可见文字（英文双引号） | 全部 |
| `<Picture 1>` | 参考图引用 | I2VA / FL2VA / L2VA |
| `<Subject N>` | 可复用的可见内容单元 | 仅 Ref2VA |
| `<Video 1>` / `<Audio 1>` | 参考视频 / 音频引用 | 仅 Ref2VA |
| `N/A` | 无声音景观 / 无非画内音乐 | 全部 |

> 标签别混用：`<Subject N>` / `<Video N>` / `<Audio N>` **只在 Ref2VA 里出现**，基础模式写这四个会干扰模型。

## 七、五种任务的对齐指令

官方共 **5 种模式**：T2VA / I2VA / FL2VA / **L2VA** / **Ref2VA**（前四种属于 `fl2va` 权重，最后一种走 `ref2va` 权重）。下面四种是「基础模式」，Ref2VA 结构完全不同，见第八节。

### T2VA（纯文生视频）
**不要对齐指令**，直接从 `integrated_multimodal_description:` 开始。

### I2VA（首帧图生视频）
第一行固定写法，后面空一行：
```
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```
正文里 `<Picture 1>` 就是 0.00 秒的首帧。结构：**首帧锚定 → 动作起始 → 连续发展 → 结果或反应**。

### FL2VA（首尾帧）
第一行固定写法，`S.SS` 是有效时长，**保留两位小数**：
```
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from [Shot N]) aligns with the S.SS-second mark of the target video.
```
> ⚠ **`N` 是实际最后一个镜头的序号，不是写死的 1。** 单镜时 `N=1`，正好和 `Shot 1` 一样；多镜时如果照抄成 `(from Shot 1)` 就是错的——这是官方原文里唯一容易抄错的地方。
> 另外注意：FL2VA 的指令行里 `Picture 1` / `Picture 2` **不带尖括号**；I2VA 的 `<Picture 1>` **带尖括号**。两种写法不要互相串。

结构：**首帧状态 → 可观察的中间变化 → 差异逐步收窄 → 尾帧状态**。首尾帧一般不倾向多镜头，让模型连续插值就好。

### L2VA（尾帧图生视频）
第一行固定写法：
```
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```
结构：**倒推一个合理的开场 → 向尾帧收敛**。`<Picture 1>` 是最后一个镜头的末帧，**不属于 Shot 1**。

## 八、Ref2VA（全参考模式）：六段结构，字段名完全不同

**这一节是 2026-09-20 核对官方 `h3-prompt-writing` 技能后补的**，初版文档漏了整个模式。走 `ref2va` 权重，用于「给一批参考图/视频/音频，让模型重写成目标视频」。

> ⚠ **千万不要把基础模式的三字段结构套到 Ref2VA 上。** 字段名、段数、顺序全都不一样。

固定六段，顺序不能变：

| 段 | 写什么 |
| --- | --- |
| `subject_definitions` | 定义每个被引用的内容及其标签。一项一行 |
| `summary` | 一段英文，开头带**方括号任务类型前缀**，概述目标视频与引用关系 |
| `retention_analysis` | 逐条写引用内容如何被保留 / 迁移 / 复用。一项一行 |
| `detailed_description` | 主体。按播放顺序逐镜写画面、动作、声音、对白，并在生效处插入引用标签 |
| `overall_soundscape` | 全片环境音与物理声 |
| `non_diegetic_music` | 只有观众能听到的配乐 |

### 四种引用标签

| 标签 | 含义 |
| --- | --- |
| `<Subject N>` | 可复用的**可见内容**：人物/动物/物体、场景/环境、服装/道具、风格/动作/姿态 |
| `<Picture N>` | 作为**具体帧**（首帧/关键帧/末帧）或构图锚点的参考图 |
| `<Video N>` | 提供剪辑源、续接起点、或整段时间结构的参考视频 |
| `<Audio N>` | 被复制或被参考的音频信号 |

两个容易搞错的点：

1. **`<Video N>` 和 `<Audio N>` 独立编号，不配对。** 同一个参考视频可能对应 `<Video 1>` 和 `<Audio 2>`，编号不同不代表来源不同。**普通参考视频不会仅因为带声音就自动产生一个 `<Audio N>`。**
2. **参考图只用来定义角色/场景/服装/风格时，不要单独建 `<Picture N>` 条目**，把图源写进对应的 `<Subject N>` 定义里即可。只有它本身当某一帧用时才单独建条目。

### `summary` 的任务类型前缀

从这六种里选，多个关系用 ` + ` 连接（**不要重复同一类型**）：

`keyframe completion` / `reference generation` / `video editing` / `video continuation` / `audio reuse` / `audio reference`

```
[reference generation + audio reference] The target video shows <Subject 3> eating a cookie in <Subject 1>. ...
```

### `retention_analysis` 的关系标记

**可见内容**（`<Subject N>` / `<Picture N>` / `<Video N>`）：

| 标记 | 含义 |
| --- | --- |
| `fully_preserved` | 引用内容被定义的用途完整保留 |
| `partially_preserved` | 仍在用，但部分被定义的特征被改变或只部分保留 |
| `attribute_transfer` | 引用特征被迁移到另一个可识别的目标主体上 |
| `weak_reference` | 只保留风格、类别、构图或氛围上的大致相似 |

**音频**（`<Audio N>`）：

| 标记 | 含义 |
| --- | --- |
| `fully_copy` | 完整源音频 1:1 作为目标视频的完整最终音轨 |
| `partially_copy` | 只复制部分时间线或部分音层，或复制后又有增删替换 |
| `reference` | 不直接复制信号，只参考音色/节奏/音乐风格/对白内容/声音质感 |
| `weak_reference` | 只保留类别或氛围上的大致相似 |

条目格式：
```
<Subject 1> (appears in [Shot 1], [Shot 3]): fully_preserved - ...
<Audio 1>: fully_copy - <Audio 1> is reused 1:1 as the target video's complete final audio track.
```

> ⚠ **`retention_analysis` 里不要写 `(Sx)` 说话人编号。**

### `detailed_description` 与基础模式的差别

| 维度 | 基础模式（T2VA 等） | Ref2VA |
| --- | --- | --- |
| 主体字段 | `integrated_multimodal_description` | `detailed_description` |
| 风格词位置 | 写在 `[Shot 1]` **之后** | 在 `[Shot 1]` **之前**用一两句英文交代 |
| 引用标签 | 不用 | 在首次出现处和生效处插入 `<Subject N>` 等 |

- 长度：生成类任务通常 **350–500 英文词**。对白密集时优先把完整口播时间线写全，而不是凑字数。**单镜不等于可以写短**。
- 直接复用参考音频里的对白/旁白/歌词时，`<d>` 内逐字保留原始词句与语言；**听不清的地方写 `[unclear]`，不要猜、不要改写**。
- 只参考音色/节奏/情绪时，**不要把参考音频里的原对白搬进目标视频**。
- `(Sx)` 按目标视频里实际发声顺序一次性分配；已绑定说话人的 `<Audio N>` 复用同一个 `(Sx)`，不另起编号。
- `overall_soundscape` / `non_diegetic_music` 里**不要重复** `<d>` 里的对白和歌词。

## 九、完整模板

### T2VA · 8 秒 · 两个镜头

```
integrated_multimodal_description: [Shot 1] Live-action, cinematic, a medium-wide shot frames a small street bakery before sunrise, warm light spilling from the open doorway. The camera pushes in with small amplitude at slow speed as a middle-aged baker with a calm, slightly raspy voice (S1) places a fresh loaf on the wooden counter and says: <d>[Chinese] 今天第一炉。</d> [Shot 2] At 00:05.000, the camera cuts to a close-up of steam rising from the sliced bread while the baker's final words carry over from the previous shot, and a hand-written price card reading "手工吐司 12元" sits beside the tray.

overall_soundscape: Wooden shutters scrape open over a quiet street as trays clink softly inside the bakery. The doorbell rings once, followed by light footsteps and the crisp sound of bread being sliced.

non_diegetic_music: A soft acoustic-guitar pattern at a moderate tempo, joined by sparse upright-bass notes and a gentle fade at the end.
```

### I2VA · 6 秒 · 单镜

```
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

integrated_multimodal_description: [Shot 1] Live-action, cinematic, the young woman shown in <Picture 1> remains beside the rain-covered train window, preserving her appearance, clothing, seat position, and carriage layout. The camera trucks right with small amplitude at slow speed as she lifts her gaze from the folded letter toward the passing city lights. Her reflection moves across the glass while the quiet, breathy young woman (S1) says: <d>[Chinese] 我下一站就下车。</d> She folds the letter along its existing crease.

overall_soundscape: The train wheels produce a steady metallic rhythm beneath a low ventilation hum. Rain ticks against the window while paper rustles softly in her hands.

non_diegetic_music: Sustained cello notes at a slow tempo with widely spaced piano tones, gradually decreasing in volume.
```

## 十、参数与提示词的关系

| 参数 | 约束 | 对提示词的影响 |
| --- | --- | --- |
| 时长 | 对齐 17k+5 帧网格（24fps） | 写剪切时间点时必须落在实际时长内 |
| 分辨率 | 短边 768px，取整到 32 的倍数 | 16:9 满画布是 1344×768；`Megapixels` 设 0.98 |
| 步数 | 默认 20；turbo 8 步 | 步数低时细节和音频质量下降，提示词要写得更明确 |
| 提示词长度 | ≤7000 字符 | 一个 8 秒片段通常写 150–350 词，够用 |

## 十一、常见问题 → 改法

| 症状 | 改哪里 |
| --- | --- |
| 画面里文字糊成乱码 | 把每一处文字都用英文双引号逐条列出来 |
| 说话时口型对不上 | 检查 `(S1)` 是否跨镜头保持一致；画外音有没有写 `while his lips remain completely closed` |
| 音频和画面对不上 | 对白写在 `integrated_multimodal_description` 里（不是 soundscape）；检查 `<d>` 内是不是只放了语言标签和原文 |
| 动作太乱、跳变 | 减镜头数；FL2VA 时删掉多余镜头，改成单镜连续插值 |
| 角色跨片段长得不一样 | 别靠文字描述，改用 Ref2VA 传参考图，或用上一段末帧做下一段首帧 |
| 该切的地方没切 | 用 `At 00:05.000, the camera cuts to` 这种明确写法，并确认时间点落在时长内 |
| 全片没声音 | `overall_soundscape` 写成了 `N/A`，或者音频 VAE 没下载 |

## 十二、给本地文字模型的指令（可直接复用）

如果你想让本地文字模型按上面的规范产出提示词，把下面这段作为系统指令：

```
你是 MiniMax H3 视频生成模型的提示词编写器。请把用户的中文创意，转写为 H3 可用的英文提示词。

输出必须严格由三部分组成，顺序固定：

1. integrated_multimodal_description:
   以 [Shot 1] 开头，紧接整体风格词（Live-action / Cinematic / 2D-animated / 3D CG 等）和初始构图。
   沿时间线描述：主体外观与位置、场景道具、动作与反应、镜头运动、说话人、对白。
   第二个镜头起用 [Shot 2] At 00:03.500, the camera cuts to ... 的格式，时间严格递增。
   镜头运动写成自然句：The camera pushes in with small amplitude at slow speed toward ...
   说话人用 (S1) (S2) 稳定编号，首次出现时交代音色与语速。
   对白写在 <d>[语言] 原文</d> 内，逐字保留，不翻译。识别短语和动作写在 <d> 外面。
   画外音必须写 says in an off-screen voiceover，并在 <d> 之后声明 while his/her lips remain completely closed。
   画面中出现的文字用英文双引号逐条列出，保留原文。

2. overall_soundscape:
   1-4 句英文，只写环境声、物理动作声、非语言人声。不重复对白和画内音乐。全片静默写 N/A。

3. non_diegetic_music:
   1-3 句英文，只写观众能听到的配乐。写乐器、速度、节奏、音量变化，不写抽象情绪词。无则写 N/A。

硬性约束：
- 提示词总长不超过 7000 字符，一个 4-15 秒片段通常 150-350 词。
- 时长按 24fps 的 17k+5 帧网格对齐，写剪切时间点不能超出总时长。
- 只输出提示词正文，不要解释、不要标题、不要 markdown 代码块。
```

配套的写法是把「片段规划表」（片段编号、时长、画幅、任务类型、上一段结尾状态）一起喂进去，让模型逐段输出。

> **上面这段只管基础模式（T2VA / I2VA / FL2VA / L2VA）。** 它和 `prompts/system-prompt.txt` 是同一份口径，`ab-test.py` 的 12 条判据也是照它写的。
> **Ref2VA 有单独的一份系统指令：`prompts/system-prompt-ref2va.txt`**（六段结构 + 四种引用标签 + 关系标记），配套模板 `prompts/templates/Ref2VA.md`。**两份不能混用**——把三字段结构套到 Ref2VA 上会产出错误结构，而且现有检查器**查不出来**（它只认三字段格式，会直接判"格式不符"，但不会告诉你真正原因）。
>
> 另外官方把这两份指南打包成了一个可安装的技能 `h3-prompt-writing`，里面 `references/base-en.txt` 和 `references/ref-en.txt` 就是全文。如果哪条规则吃不准，直接读那两份原文最省事。

### 还缺什么（诚实清单）

| 缺口 | 影响 | 补法 |
| --- | --- | --- |
| `ab-test.py` 不支持 Ref2VA | 拿它跑 Ref2VA 产出会一律判"格式不符"，**且不说明真正原因** | 给检查器补一套六段结构的判据 |
| 「提示词 ≤7000 字符」未证实 | `ab-test.py` 把它当硬判据用 | 查平台 API 文档原文；查不到就降级为警告 |
| 以上四种基础模式都还没跑过真实生成 | 提示词写法只经文字模型自检，**没经 H3 实际出片验证** | 生成机开机后跑第一条 |
