# assets/ 参考素材

放给**生成机**用的参考素材原件：首帧图、尾帧图、参考视频、参考音频。

## 为什么原件必须留在本地

素材上传到实例后，会落在实例自己的目录里（ComfyUI 的 `input/`）。**实例一旦释放，这些文件全没了。** 本地这份是唯一原件，所以别只存在实例上。

## 建议的子目录

```
assets/
├── characters/     角色参考图（同一角色跨片段复用同一批图）
├── scenes/         场景参考图
├── frames/         首帧 / 尾帧图，按片段编号命名
├── videos/         参考视频（动作、运镜参考）
└── audio/          参考音频（音色、音乐参考）
```

## 命名建议

按片段编号走，方便和提示词对应：

- `frames/S01-first.png`、`frames/S01-last.png`
- `characters/主角-正面.jpg`、`characters/主角-侧面.jpg`

## 引用规则（重要）

H3 用**标签**引用素材，**顺序必须和上传顺序完全一致**：

| 标签 | 类型 | 上限 |
| --- | --- | --- |
| `<Picture 1>` … `<Picture 9>` | 参考图 | 9 张 |
| `<Video 1>` … `<Video 3>` | 参考视频 | 3 段，每段 2–15 秒，总计 ≤15 秒 |
| `<Audio 1>` … `<Audio 3>` | 参考音频 | 3 段，每段 2–15 秒，总计 ≤15 秒 |

混合输入时**所有类型文件总数 ≤ 12**，请求体 ≤ 64MB。

每个素材都要在提示词里明确它负责什么（身份、风格、动作、运镜、音色）。不分配任务的话，模型会自己乱猜。

## 一致性靠素材，不靠文字

模型不会记住你的故事。角色长相、场景风格要跨片段保持一致，只有两条路：

1. **Ref2VA**：传同一批参考图，用 `<Picture N>` 锁定角色和风格
2. **FL2VA**：用上一段的末帧做下一段的首帧，靠画面自然衔接

文字只负责描述这一段里发生了什么。
